# FootballGM Sim: rules for the AI coding agent

A pro football league simulator and GM game. It starts from the real league as it stood after the 2025 season, with every name made fictional. Two modes share one engine: **GM Mode** (one team's decisions come from the user) and **Simulation Mode** (all 32 teams run by AI). Every game is simulated snap by snap.

The owner does not write code. Changes must be explainable in plain English and checkable by using the game, reading its stats pages, or reading the calibration scorecard.

Planning notes live in the owner's Obsidian vault: `Projects/FootballGM Sim Project/` (`01 - Overview`, `02 - Roadmap`, `03 - Devlog`). The roadmap defines the phases and each phase's "Done when" checks. `docs/overview.md` and `docs/roadmap.md` are snapshots of those notes; the vault is the source of truth.

## Hard rules

1. `packages/foundation`, `packages/sim-core` and `packages/game-engine` never use browser APIs (no `window`, `document`, DOM, IndexedDB, `localStorage`) or Node-only imports. They must run unchanged in a browser, a Web Worker, and Node.
2. Never use `Math.random()`, `Date.now()`, `new Date()` or `performance.now()` in simulation logic. All randomness comes from the seeded `RngStreams` in `sim-core`; each area of the sim uses its own named stream (`RNG_STREAMS`) so new random draws in one area never reshuffle another.
   In the simulation packages, also avoid `Math.exp/log/pow/sin/cos/...` and the `**` operator: browsers may round them differently, so the same seed would play out differently in Chrome and Safari. Use `dmath` from `sim-core` (exact `+ - * /` underneath). `Math.sqrt`, `Math.floor`, `Math.round`, `Math.min/max/abs`, `Math.imul` are fine. `tests/guardrails.test.ts` enforces this.
3. League time is the in-game calendar, never the real clock.
4. **Rules as data.** Every league rule (salary cap, contract rules, roster limits, overtime, kickoffs, playoff format, tiebreakers) lives in the versioned config in `rules/`. Every tuning number lives in config. No magic numbers in logic. Exact NFL values are checked against the current CBA or rulebook in the phase that first uses them, never typed from memory.
5. **Money is whole dollars** (`Dollars` in `sim-core`), never floating point. Every cap or contract rule gets a unit test with a worked example.
6. **Determinism.** Same starting data + same seed + same decisions = same league history. Don't iterate over unordered structures in a way that changes results; don't depend on timing.
7. **Truth vs. perception.** Players' true ratings are never shown directly; screens read through the perception layer (what the team's staff believes).
8. **Everything has a reason.** AI decisions, contract demands, play calls, and player development record why they happened.
9. **The league stays legal.** Roster sizes and cap compliance are validated after every transaction; validators run in tests.
10. **No real names or trademarks** in committed code or data: no real player or coach names, no NFL team names, logos, or "championship game". Real cities are fine. Restricted source data (e.g. Madden ratings) stays in `pipeline/private/`, which is git-ignored. Never commit it.
11. Run `npm test` and `npm run typecheck` before every commit. Never commit with failing tests.
12. Prefer simple, readable code over clever code. Add a short comment explaining _why_ for anything non-obvious.

## Working style

- Work **one roadmap phase at a time**, each on its own git branch (`phase-1-league-skeleton`, etc.). Merge to `main` when the phase's "Done when" items are met.
- At the start of a phase, read this file and the phase's goals, then **propose a plan before writing code**.
- Explain changes in plain English for a non-programmer. Say what changed in the game's behavior, not just in the code. Say how to _see_ each result (which screen, which seed, which scorecard line).
- Commit small and often so any change can be rolled back.
- Calibrate with evidence: many seeds and many seasons, compared against the real-NFL targets. Report honestly when a "Done when" item is only partly met.
- At the end of each phase, write a devlog entry in `docs/devlog/` (what was built, what surprised us, what broke, one screenshot), append the same entry to the Obsidian note `03 - Devlog`, and tick the roadmap boxes in `02 - Roadmap` that were actually verified (then refresh the `docs/` snapshots).
- Never push, publish, or deploy without the owner's go-ahead.

## Layout

```
packages/foundation/   shared basics: seeded RNG, dmath, money, dates, positions and the rating model
packages/sim-core/     league logic: rules, data model, seasons, standings, AI. No UI, no browser or Node APIs
packages/game-engine/  the play-by-play engine (separately testable and calibratable); depends only on foundation
calibration/           real-NFL targets and fitted shapes (targets.json, built by the pipeline from nflverse)
apps/web/              the game: React + Tailwind + shadcn/ui; the sim runs in a Web Worker (src/sim/)
apps/runner/           Node CLI for headless calibration runs and experiments (tsx)
pipeline/              real-league import (Phase 6); pipeline/private/ and pipeline/cache/ are git-ignored
rules/                 versioned league rules config (one file per season)
tests/                 repo-wide guardrail tests
docs/                  overview and roadmap snapshots, devlog
```

## Tech notes

- TypeScript everywhere, npm workspaces. Packages are consumed as TypeScript source (no build step); imports have no file extension.
- The web app uses Tailwind v4 with shadcn/ui-style components in `apps/web/src/components/ui/` (`components.json` is set up, so `npx shadcn add <component>` works from `apps/web`). Colors come only from the theme tokens in `src/index.css`, which has light and dark sets.
- The page talks to the simulation only through the worker messages in `apps/web/src/sim/protocol.ts`. The worker owns the open league, saves it to IndexedDB (Dexie, `sim/db.ts`), and answers screen requests with data from `sim-core/src/views.ts`. Add a screen by adding a view function in sim-core, a method in `protocol.ts`, and a handler in `sim.worker.ts`.
- **League data model** (`sim-core/src/league/schema.ts`): zod schemas; TypeScript types are inferred from them and the same schemas validate imported files. A league is plain JSON (no classes). `serializeLeague()` sorts keys, so the same league is always byte-identical; `fingerprint()` hashes the file text and is shown on screen. Changing the schema in a way old files can't load means bumping `LEAGUE_FORMAT_VERSION`.
- **Rules** (`rules/2026.json`, loaded by `sim-core/src/rules.ts`): every block carries a `source` note saying where the numbers came from.
- **Ratings** (`sim-core/src/players/`): 28 attributes (0-100, our own scale), position overall = weighted average shifted so an average starter shows 75 everywhere. Weights, physical profiles, and sizes are config in `positions.ts`; generation tuning is in `generate/config.ts`.
- **Perception** (`sim-core/src/perception.ts`): screens get ratings only via `perceivePlayer()`; a guardrail test fails if `apps/web/src` touches `.ratings`, `.hidden`, or `.personality`.
- **Decisions** (`sim-core/src/decisions.ts`): `askTeam()` routes each team decision to the AI (answers with a reason) or queues it for the human (`pendingDecisions`). Add a decision kind by extending `DecisionRequestSchema` and `AI_POLICIES`.
- **Seasons** (`sim-core/src/season/`): `flow.ts` moves the calendar one step at a time (`advance`), `actions.ts` maps the sim buttons onto it, `schedule.ts` builds the 272-game schedule (formula from the rotation tables in the rules, then a seeded week search; `validate.ts` checks every rule), `standings.ts` + `tiebreakers.ts` + `seeding.ts` implement the official NFL tie-breaking procedures (each step records a reason), `playoffs.ts` the 7-team bracket with reseeding, `draftOrder.ts` the draft order with tied clubs rotating each round. Games are placeholder scores (`placeholderGame.ts`) until the Phase 3 engine replaces `playGames()` in `flow.ts`.
- Coin tosses in tiebreakers hash the league seed, season, and clubs instead of drawing random numbers, so computing standings (any number of times) never changes the future. Keep anything a screen can trigger free of RNG draws.
- A new fictional league plays a placeholder 2025 season at creation (`historyOnly`: no roster moves, since contracts come after), so 2026 has real standings for the schedule, same-place games, draft order, and History. The first league day is the day after that championship (Feb 9, 2026).
- League saves carry `formatVersion` (now 21). Saves from format 2 on are upgraded automatically (`upgrade()` in `serialize.ts`); older ones are refused with a plain-English message. Add an upgrade step whenever a change should keep old saves working.
- Team identities and conference names are placeholders (`generate/teams.ts`, rules file) until the Phase 6 naming session; none may be a real pro team's nickname.
- **Package layering:** `foundation` ← `game-engine` ← `sim-core` ← apps. The engine never imports sim-core; sim-core builds lineups and calls `simulateGame()`. Shared types the league stores (box score, stat lines) are defined in the engine, and sim-core's zod schemas are checked against them at compile time.
- **The game engine** (`packages/game-engine/src/`): `engine.ts` runs a game snap by snap; `playcall.ts` is the tendency-table play caller; `units.ts` turns a lineup into unit strengths; `boxscore.ts` builds stats from the play list; `calibrate.ts` measures seasons for the scorecard. Real-NFL shapes (yardage quantiles, completion by depth, kicking) come from `calibration/targets.json` (`REAL` in `config.ts`); the engine's own knobs are in `TUNING`. When tuning, change one knob at a time and judge by `npm run sim -- --calibrate` across several seeds, never one season.
- Nudging a random draw: use `shiftedUniform()` (log-odds shift). Never add to a uniform number and clamp it: that piles draws onto the extreme value and, with a tail, produces 200-yard plays (Phase 3 found this the hard way).
- Every game has its own seed (`gameSeed()` in `season/flow.ts`), so games don't depend on play order. Season stat totals count regular-season games only; playoff box scores stay on the games.
- Play-by-play is NOT in the league file: the worker stores it in the `playLogs` IndexedDB table for the current and previous season (`apps/web/src/sim/db.ts`), and `gameView()` renders it as text. Box scores and stats are in the league file.
- `tests/calibration.test.ts` keeps the core stats inside the real ranges in CI; if a change breaks it, run the scorecard.
- **Who plays (Phase 4b).** Teams carry a depth chart (`team.depthChart`: automatic, or a custom order per spot). `season/depthChart.ts` builds it (best overall at each spot, counting second positions via `familiarity`) and hands the engine a `DepthChart` with injured players left off. Inside a game, `game-engine/src/sideline.ts` picks who is on the field before each snap: tired players (energy drains per snap, by stamina) give way to the next man, and players hurt during the game leave. Fatigue drains and injury rates are in `TUNING.fatigue` / `TUNING.injuries`; the real targets are in `calibration/people.json`.
- **Injuries (Phase 9b, `season/injuries.ts`).** The engine decides who gets hurt in a game and whether he came back; practice and camp add the injuries no game shows, so the total costing games matches the real injury reports (`calibration/injuries.json`, `npm run pipeline -- injuries`: 2016-25 reports, weekly rosters and snap counts; practice severities are the real total minus the engine's in-game share, computed at load). Each injury gets games out (in-game: the real distribution from people.json), a body part from the real mix for its severity (reinjury: a recent return makes the same part `samePartRelativeRisk` times as likely), a severity word, a kind (game, practice, camp, non-football) and a report status. `player.injury` means he misses games (`gamesRemaining` counts his team's games; Out, or Doubtful/Questionable on his last missed game); `player.knock` means he's listed Questionable but plays, a step slower (`knockPenalty` on speed, acceleration, agility in `asLineupPlayer`). `player.injuryHistory` keeps every one. Severe leg injuries cost speed for good (`lastingDamage`, judgment). Camp: injuries at camp opening and over the preseason weeks, non-football injuries start players on the NFI list (Reserve/NFI at cuts like PUP). The offseason heals `offseasonRecoveryGames`; longer injuries carry into camp (PUP). Free agents heal weekly. AI teams put players on injured reserve from 6 games out (`ROSTER_AI.injuredReserveFromGames`; the rule allows 4), or from 4 when the position is short of healthy players, so the 53 refills there. Practice and camp injuries hit positions in proportion to their real in-game injury rates (`specialistExposure` for kickers, punters, snappers). Knobs in `INJURY_MODEL` (`season/config.ts`); `npm run sim -- --injuries N` compares injuries, reserve lists and the weekly report with the real numbers. Screens: `/injuries` (report), `/development` (risers and fallers), and the player page's career-arc chart and injury history (`lifecycle/views.ts`, `perceiveHistory`/`perceiveChange` in perception.ts).
- **EPA** (`game-engine/src/epa.ts`): every run and dropback gets expected points added from the expected-points table in `calibration/matchups.json`, with nflverse's conventions (touchdown 7, safety -2, half end 0). The pipeline measures the real targets with the same table so the two compare fairly.
- **Game management (Phase 5a).** `winprob.ts` is a logistic win-probability model fitted to real outcomes (weights in `calibration/situations.json`); every snap stores the home team's chance as `play.wp`. `decisions.ts` makes 4th-down and 2-point calls by comparing each option's win probability (the analytics baseline), then applies real coaches' caution and the team's `gameStyle` (aggressiveness, 2-point aggressiveness, adaptability; 0.5 = typical, set by coaches from Phase 10). Notes on plays explain each call. `review.ts` handles close calls, booth reviews and coach challenges. Halftime adjustments and a momentum knob (zero by default) live in `TUNING.adjustments` / `TUNING.momentum`. Situational scorecard ranges are widened to two standard errors of one season's sampling noise (`targetsNote` in `situations.json`).
- **Special teams and the elements (Phase 5b).** Kickoffs follow the 2026 dynamic-kickoff rules in `rules/2026.json` (`game.kickoff`): the real 2025 mix of touchbacks, landing-zone kicks, short and out-of-bounds kicks, moved by the kicker's leg, wind and altitude; returns pit the returner's speed against the kicking team's coverage. Onside kicks are rule-based (trailing by at most `onsideMaxDeficit` late in the 4th quarter or overtime), at the real recovery rate. Punts pin near midfield, and muffs, blocked punts and field goals, and fakes happen at real rates (`TUNING.specialTeams`, `calibration/elements.json`). Each team has a `stadium` (roof, surface, elevation; no names). `sim-core/src/season/weather.ts` draws each game's weather from the home city's climate for that week with the game's own seed, stores it on the game, and passes `conditions` to the engine; `game-engine/src/weather.ts` turns them into effects measured from real games, relative to the average real conditions (the engine's base tables already include average weather). Dome vs. cold-or-windy lines are "info" on the scorecard: real teams in cold cities differ in quality, so they aren't pass/fail.
- **Play and watch.** `playGameNow()` in `season/flow.ts` plays one of this week's games early (the week's sim skips games already played); results match simming the whole week because games, weather and injuries have their own seeds and depth charts are set per team. The web app's `/game/:id/watch` replays a game's play-by-play live (`components/LiveTicker.tsx`).
- **The real league (Phase 6).** `npm run pipeline -- league` (`pipeline/src/league/`) builds the starting league from nflverse end-of-2025 rosters, bios, snap counts and scores, the end-of-2025 coaching staffs (`pipeline/private/coaches-2025.csv`, collected from public team season pages), and the private Madden ratings file (`pipeline/private/madden/ratings-2025.csv`). Madden attributes are mixed into ours (`MADDEN_MAP` in `madden.ts`), then moved onto our scale per position so real starters match the starters of our generated leagues (`ratings.ts`); players Madden lacks get ratings around a target from their 2025 role and draft slot. Then (Phase 6b, `performance.ts`) each regular's overall moves part of the way toward what his 2025 production implies (per-position metrics from nflverse stats, Next Gen Stats and PFR advanced stats; skills move, physical attributes don't), each team's regulars move with the team's real 2025 point differential (so team strength spreads as in generated leagues), and kickers and punters are lined up with the engine's `TUNING.averageKicker`. Injury traits come from 2023-25 injury history and Madden's injury/toughness, rescaled to the generated players' averages; potential grows with draft pedigree; careers carry real regular-season stats since 1999 (`careers.ts`). The build also writes a private sanity sheet (`sanity.html`, top 10 per position with real names). `npm run sim -- --calibrate --league <file>` runs the scorecard from the real league. Names come from a hash of each person's id (`names.ts`) and are redrawn if they match any real player or coach; colleges map to fictional schools. `sim-core/src/realLeague.ts` (`assembleRealLeague`) turns those facts into a league, runs the real 2025 season through the normal standings and draft-order code, and starts 2026; `startRealLeague` makes each new game from the file with its own name and seed. Outputs live in `pipeline/private/out/` (league file and a private report with real names), plus a copy in `apps/web/public/private/` that the New League dialog loads; both are git-ignored. `tests/realLeague.test.ts` checks the build and skips where the private files are missing (CI).
- **Contracts and the salary cap (Phase 7).** Cap rules live in `rules/2026.json` (`cap`: caps by year, Article 26 minimum salaries, proration limit, top 51, June 1 designations, tags, RFA tenders, fifth-year option tiers, veteran salary benefit, minimum cash spending, the rookie scale), every value with its CBA or NFL source. `sim-core/src/contracts/`: `contract.ts` (cap hit, cash, proration, guarantees: pure functions), `cap.ts` (cap and minimums by year, tenders, rookie slots), `team.ts` (cap sheet with the offseason top-51 rule, dead money, carryover, cash spending), `operations.ts` (release pre/post June 1 and the designation, trade, restructure with void years, extension, pay cut, fifth-year option; each with a preview and a reason-carrying transaction), `tags.ts` (Cap Percentage Average from `league.salaryHistory`; 2026 uses the published values), `generate.ts` (market value by rank in the tag category; contracts for fictional leagues and old saves), `upkeep.ts` (each new League Year: record salaries, cash, carryover and year-end incentive netting; void-year acceleration; options; re-signing and a simple free-agent market as placeholders until Phase 12; restructure-then-release to get under the cap; minimum-deal roster filling until Phase 8). Money is always whole dollars. `contracts.test.ts` has a worked example per rule; `legality.test.ts` sims 20 seasons and checks every team stays legal.
- **Real contracts and the cap screens (Phase 7b).** The real league's contracts come from each team's public cap page as archived closest to Feb 9, 2026 (`pipeline/src/league/capPages.ts` fetches them once from the Internet Archive into `pipeline/private/cap/teams/`; facts only, never committed), matched to players by name. Each year's bonus proration is stored as that year's share, so cap hits and accelerations equal the page; per-game roster bonuses count only their likely part (the rest becomes an unlikely incentive) and veteran-minimum deals get the salary benefit, both read off the page's own cap numbers. Years after 2029 and signing years come from nflverse's contract data (`contracts.ts`, `pipeline/cache/`). A player whose deal ended with 2025 is a pending free agent; void years still charging his team become dead money tied to him; players released before their team's page date start as free agents. Team dead money comes from the pages, carryover from an archived cap-space table (`pipeline/private/cap/`). `validate.ts` writes the cap validation into the private report and `cap-validation.json` (contracts reproduced to the dollar, year by year, and team totals with the top-51 rule against the published Feb 10 figures, each miss explained); `tests/realLeague.test.ts` checks it locally. The rookie scale knots in `rules/2026.json` are fitted by `npm run pipeline -- rookies` (only cap shares are committed). Screens: `sim-core/src/contracts/views.ts` (`contractView` with "what if" previews measured on a scratch copy of the league so the top-51 rule is exact, `capSheetView`, `makeCapMove` for league-office moves until GM Mode), shown by `ContractPanel` on the player page and `CapSheet` in the team page's Salary cap tab. Contract data from OverTheCap (direct or via nflverse) is private, like the Madden file.
- **The League Year and roster rules (Phase 8).** `rules/2026.json` `calendar` has every dated event (checked against the NFL's 2026 and 2026-27 calendars; later years follow the same rules) and `roster` the roster rules (90/53, 48 game-day actives, practice squad of 16 + 1 international with up to 6 veterans and the CBA's weekly pay, elevations, injured reserve and PUP minimums and returns, waiver rules). `season/calendar.ts` turns them into dates (cached per season). `CALENDAR_STAGES` are the stretches between events: `offseason` (to the new League Year in March, when `openLeagueYear` runs), `free-agency` (to the draft), `draft` (draft day, pick by pick, Phase 11b), `after-draft` (to camp), `preseason` (`week` = next preseason week), `cutdown`, then the season. `flow.ts` `advance()` runs each event: `draft/day.ts` (draft day and the undrafted rush, Phase 11b), `roster/preseason.ts` (three games with starters resting; a showcase grade per player; small capped boosts for standouts with room to grow), `roster/upkeep.ts` (camp PUP list, final cuts with the waiver rush and practice squads, weekly IR/returns/53/practice squad/elevations, season-end futures deals, placeholder retirement until Phase 9). Players carry `roster` (active, practice-squad, injured-reserve, pup, nfi), `reserve`, `elevations`, `retiredAfter` and `preseason`; preseason games live in `league.preseasonGames` (ids from 100000) so nothing counts them as real games. `roster/moves.ts` has the moves (waivers with claim order, reserve lists, practice squad, promotions); `roster/legality.ts` checks every rule. `setTransactionAudit(checkLegal)` runs it after every recorded transaction (moves made together go in `batch()`, audited once at the end); the runner's `--seasons` and the tests use it. Salary is paid weekly in the season: a release or trade leaves what was paid on the old team's cap (`earnedSoFar`, `contractAfterTrade`), and deals signed mid-season pay only the weeks left. Roster AI tuning is in `roster/config.ts`.
- **Trades and the roster screens (Phase 8b).** `roster/trades.ts` (`previewTradeDeal` on a scratch copy, `makeTrade`: players and picks, refused outside March-to-deadline, over the cap or roster limit, or for practice-squad players), `roster/office.ts` (`rosterManagementView` and `makeRosterMove`: waive, injured reserve, activate, promote, elevate, sign; each move is tried on a scratch copy first and refused with the reason if it breaks a rule), `roster/views.ts` (transactions log, calendar page, camp report, trade assets), `roster/jerseys.ts` (unique numbers, swept after every `advance`). The scratch copy (`contracts/views.ts` `scratch`) copies everything a move can change in place. Web pages: `/trade`, `/transactions`, `/calendar`, `/camp`, and the team page's Manage roster and Transactions tabs. Until GM Mode the league office can act for any team.
- **Player lifecycle (Phase 9a).** `sim-core/src/lifecycle/`: `curves.ts` reads the real age curves from `calibration/lifecycle.json` (each position's change per year by age, measured on the same players season to season: share of snaps, quarterbacks by EPA per play; fullbacks use the average curve, specialists a hand shape). `development.ts`: at the new League Year (70% of the year) and in camp (30%, plus a little extra for preseason standouts, replacing Phase 8's boost), young players close part of the gap to their hidden potential (the share each year follows the real curve's timing, at most `maxGrowthShare`; more with work ethic and playing time); past the peak they decline along the real curve (`declinePointsPerSd`), physical traits first after 30. Luck moves young players' potential too; after the peak it fades. Small weekly changes in season (after the whole week is played). Notable changes go to `league.development` (this season's rounds, with reasons); `player.ratingHistory` gets a line at each season's end. `retirement.ts` replaces the placeholder: odds on the log-odds scale from age against the position's real late retirement age, plus decline from his best, a title, an expiring deal, a fringe role and injury; free agents nobody played all season retire. Close position battles: `campEdge()` in `season/depthChart.ts` gives this year's preseason grade up to ±1.25 points when choosing starters (a 3-point gap always holds), and the depth chart notes "Won the job in camp". Growth is sized by potential, not by the real curve, because snap share can't show a full-time starter improving; decline size and the placeholder draft's room to grow (`DRAFT_CLASS.growthMean`, `growthByPosition` for positions that wear out sooner, `specialistBonus` for kickers, punters and snappers arriving close to ready) are tuned so 30 seasons keep every position's starters level (`--lifecycle 30`; `--out` saves the final league and `--calibrate --league <file>` scores it). The 10-season legality test also checks age mix, starter drift, stars and career arcs.
- **Coaches (Phase 10a, `sim-core/src/coaches/`).** Each team has twelve staff (`STAFF_ROLES`): HC, OC, DC, special teams, four position-group coaches (SKILL, OLC, FRONT, DBC), strength (STR), head trainer (MED), two scouts. Coaches have skills (0-100, including `health`) and a `style` in the real units of `calibration/coaching.json` (offsets from the league mean; generated coaches draw it from the real `trueSpread` between team-seasons). `style.ts` `staffInput()` hands the engine the OC's offense (`offenseStyle`: pass rate, no-huddle tempo, deep share, 11 personnel, play-calling skill), the DC's defense (`defenseStyle`: blitz, man coverage, stacked boxes, skill), the HC's game management (`gameStyle` aggressiveness from `STYLE_MAPPING`) and discipline (pre-snap penalties). The engine applies styles by tilting its real tables (`tilt()` in onfield.ts) and the skill edge through `playShifts` (`TUNING.coaching`, zero-sum). `fit.ts`: each scheme prizes skills by position; fit (-1..1, against an average starter so typical players are neutral) moves game-day ratings and depth-chart rank by up to `FIT_OVERALL_POINTS` and development by `FIT_DEVELOPMENT`. `effects.ts`: position coach and HC development multipliers (into Phase 9's `coaching` hook), strength coach injury risk, trainer recovery; all 1 for a typical coach. Real league: `pipeline/src/league/coachStyles.ts` gives 2025 coordinators their team's 2025 tendencies and head coaches their career 4th-down/2-point habits, shrunk by sample noise (private). Screens: team Staff tab, coach profile with philosophy chart (`PhilosophyChart`), fit tags on roster and depth chart, fit on the player page. Saves are format 11 (old saves get styles and full staffs).
- **The coaching carousel (Phase 10b, `coaches/carousel.ts`).** Coaches carry `career` (a line per season: team, job, the head coach above them for coaching trees, head coaches' records), `contractThrough`, `reputation`, `interim`, `retiredAfter` and scouts' `specialty`; `league.coachingMoves` logs every move with its reason. Flow hooks: `inSeasonFirings` after regular weeks (interim = the coordinator with the most leadership, his side's best position coach steps up), `blackMonday` when the regular season ends (head coaches by results against `expectedWinShare` from roster strength, tenure grace, playoffs, losing streaks, contract; coordinators by unit rank), `hiringRound` after each playoff round and `offseasonStaffing` at "complete" (last hires, coach development, contract renewals, retirements). Interview and signing timing follow `rules.staff` (checked against the 2023-25 anti-tampering policy as reported): interviews from three days after the candidate's last game, no signing until his season is over; teams may wait for a clearly better candidate still in the playoffs. A new head coach keeps or replaces each coordinator; newcomers join a search only when its field is thin. Odds in `CAROUSEL` (`coaches/config.ts`) are tuned to the real 7.2 head-coach changes a year between seasons and 1.65 during them (`calibration/coaching.json` `headCoachChanges`, from nflverse schedules); the 10-season legality test checks the band. Real head coaches start with their real careers since 2000 (private). Screens: `/coaching` (firings, searches with interviews, hires, open jobs with league-office hiring), coach profile career and tree, league-office firing. Saves are format 12.
- **Scouting and draft classes (Phase 11a).** Nobody sees true ratings: `perception.ts` returns truth plus an error fixed per viewer and player by a hash (`scouting/noise.ts`, no random draws, so screens never change the future), scaled by how uncertain the read is: NFL tape (snaps, seasons), own team, the viewer's scouts (skill vs. the league's typical scout, budget) and, for prospects, study points (`team.scouting.points`). Most of the error is shared by the whole league; a prospect's shared read starts at what his class rank usually is (`anchorRank`, the real draft slot for the real class) and moves toward the truth as he's studied; each team adds its own smaller error; the league office (`settings.viewingAs` null, the default "Viewing as") sees only the shared part. Tuning is `SCOUTING` in `scouting/config.ts`. Classes (`scouting/classes.ts`) live in `league.prospects` (not players) until draft day; the next class appears right after each draft, with positions and ages by round from `calibration/draft.json` (`npm run pipeline -- draft`), and drills from physical ratings on the real distributions (`measurables.ts`; the reverse for the real 2026 class, `pipeline/private/out/class-2026.json`, private). The combine and pro days (`scouting/study.ts`) measure prospects; scouts' assignments (region and position group) add weekly study from September to April. Teams draft from their own boards (`scouting/value.ts`). `npm run sim -- --draft 20` compares hit rates by round with real drafts.
- **Draft day (Phase 11b, `sim-core/src/draft/`).** The `draft` calendar stage holds the draft open so the draft room can stop anywhere: `day.ts` (`onTheClock`, `makePick` for the league office's choice, `aiPick`, `simPicks`, `draftAction`, `finishDraft` with the undrafted rush). Picks carry `compensatory` and `selection`; this year's unused picks trade on draft day. Boards (`boards.ts`): each team's scouted value plus need (its staff's read of its starters, age and depth) weighed by a philosophy fixed per team by a hash until Phase 13's GMs, or a board set by hand (`team.scouting.board`). Trades (`tradeOffers`): a team further down moves up for the top of its board when he's likely gone first and it gains `tradeUp.surplus` more board points than the team on the clock loses (the bar scales with the pick's worth), paying the cheapest set of picks worth about 1.42 times the pick's career value (`values.ts`, `calibration/draft.json` `pickValue`; future picks a round later); the real targets are `trades` in draft.json (nflverse/nfldata trades). Compensatory picks (`compensatory.ts`): CBA Appendix V from `rules.draft.compensatory` (UFAs who changed teams are recorded in `league.freeAgentMoves` by the free-agent market), awarded at the new League Year; the real 2026 draft uses the real order and compensatory picks (`RealLeagueInput.draftOrder`). Screens (`views.ts`): draft room, big board, mock drafts, draft history with retro grades (seasons started vs. real picks at the slot). Tuning in `DRAFT_DAY` (`draft/config.ts`); `npm run sim -- --draft 20` also reports trades and prices. Saves are format 14.
- **Free agency and negotiation (Phase 12a).** `calibration/market.json` (`npm run pipeline -- market`, from nflverse/OverTheCap contracts; only derived curves are committed) has pay by position and rank as a share of the cap, free agents' pay by tier, contract length by age, guarantees by pay, and how many players change teams, re-sign or extend each year. `contracts/market.ts` `marketValue()`: rank among veterans at the position by the league office's read adjusted for age (the real age curves), the real pay at that rank blended with the league's own deals (`compsWeight`, kept within `compsBand` of the real curve so bidding wars can't spiral), typical years and guarantees. `people/agents.ts`: fictional agents with styles (hardball, fair, relationship-driven, money-only), assigned to players by a hash. `contracts/negotiation.ts`: demands (market value moved by agent, ego, the money priority; loyalty discounts the player's team), a team's appeal (winning, role by its own read, location by hash, scheme fit, weighted by his priorities), and `answerOffer` (meeting the ask in every part always works; below the agent's walk-away share ends talks; otherwise a counter at the agent's pace until patience runs out; every answer has a reason; no random draws). `contracts/freeAgency.ts`: the re-signing window before the League Year (teams get under the cap, re-sign who they want unless the player tests the market (`testMarket`), one franchise or transition tag on a star whose talks failed, restricted and exclusive-rights tenders that hold `player.rights`), free agency from the League Year (`league.freeAgency`: day by day for a week, then weekly to the draft, a late round every three weeks to camp): AI teams bid on the players they value most above their ask (need, own read, budget = room less draft picks' deals and a reserve, offers out up to twice their room), players take the best offer by everything they care about once it clears what they hold out for (falling while unsigned), offer sheets for tendered players with the CBA's matching days and compensation picks, weekly in-season extensions. Rules (CBA Articles 7-10 and 42) are in `rules/2026.json` `freeAgency`. Screens: `/free-agency` (market board, signings, tags and tenders) and `/negotiate/:id` (`contracts/marketViews.ts`: demands, appeal, offers by the league office with cap previews). `npm run sim -- --market N` compares a League Year's market with the real one. Saves are format 15.
- **Moods, the locker room and disputes (Phase 12b, `sim-core/src/people/`).** `morale.ts`: every player on a team has `player.mood` (0-100, 50 = content) with points by factor: winning (team's win share, by his winning priority), role (snaps vs. whether he thinks he should start: his true overall, inflated by ego, vs. his teammates'), pay (his deal's cap share vs. his market value's, by the money priority; early rookie deals count a quarter), scheme fit, the veterans' leadership, loyalty and an open dispute; low temperament amplifies everything. `updateMoods` runs weekly in the regular season (35% of the way to the target) and at the League Year and camp (60%). `teamChemistry`: moods weighted by leadership, minus unhappy big egos. Effects are small on purpose (`MORALE`): development x(1 +- 6%) via the coaching hook, game-day ratings up to +-0.6 points from mood and +-0.4 from chemistry (`ratingsInScheme`'s extra shift), and the ask to his own team +-6% (an unhappy player's loyalty discount fades; `testMarket` rises). `disputes.ts`: at camp, unhappy stars (market value 5%+ of the cap, paid under 65% of it, at most two years left) may hold out (fined `campFinePerDay` a day, misses preseason games and half of camp's development), hold in (a quarter), or ask to be traded; very unhappy players who matter may ask out during the season before the deadline. Teams answer with a reason: an extension through the normal talks (core players; up to the usual limit at camp, rising each preseason week; 5% over for a trade request), a trade for picks (`tradeAway`: the team that would start him and values him most, paying the cheapest one or two early picks worth his value at a discount), or waiting. Holdouts end by cutdown day; requests lapse at the League Year if his mood recovered. `league.disputes` keeps three seasons. Counts are tuned to judgment ranges from 2024-25 camp coverage (`REAL_DISPUTES`: 3-8 holdouts and hold-ins, 1-5 trade requests a year), reported by `--market`. Screens (`people/views.ts`): mood card on the player page, Mood column and dispute tags on rosters, the team page's Locker room tab, and the league page's Holdouts and trade requests card. Saves are format 16 (moods start empty, filled at the next update).
- **Front offices and the trade market (Phase 13a, `sim-core/src/front-office/`).** `league.executives`: a GM and an owner per team (`executives.ts`; generated from the seed with archetypes dealt out so every league has a mix; GM knobs -1..1 `futureDiscount`, `analytics`, `capAggression`, `tradeAppetite`, `loyalty`, `risk`, plus `skill`; owner `patience`, `budget`, `meddling`, `ambition`). The real league's GMs come from their teams' measured habits (`npm run pipeline -- frontoffice` writes private `front-office-habits.json` from `pipeline/private/gms-2025.csv`: trades a year, draft-day trade direction, 2026 dead money, owners' head-coach turnover since 2000; `pipeline/src/league/frontOffices.ts`, shrunk by tenure). `evaluate.ts` `updatePlans`: each GM reads his team (own staff's read now and two years out with the age curves, last record, the quarterback, cap room for three seasons) and calls contend / retool / rebuild with reasons (`team.plan.stance`), at the League Year, camp and the week before the deadline. `strategy.ts` plugs the GM into existing AI: `teamLimit` (contenders pay for veterans, rebuilders for youth, analytics GMs by position value, loyal GMs for their own), `teamBudget` (cap aggression, owner budget, rebuild reserve), draft boards (`philosophy()` from the GM), restructures with void years for cap-aggressive GMs at the League Year (`aggressiveRestructures`), early extensions for patient or loyal GMs. Trades: `tradeValue.ts` values players and picks in draft career value (a season's value from the overall, `seasonValue`; control years from the contract; contract surplus at `dollarsPerValueShareOfCap`; injuries spill into later seasons; needs, roles, window, GM biases, a per-team-player-season gut feel by hash; picks at projected slots, future ones discounted by the GM), with a `neutral` judge (true ratings, no biases) for reports and tests. `tradeAI.ts` `answerTrade`: yes when what a team gets beats what it gives by its margin (less for risk-takers and keen traders, more with each recent trade with that partner; `memoryMax` in `memoryDays` refuses), with reasons and a counter (`findCounter`); `executeTrade` records both views and the neutral judge's in `league.tradeHistory`. `tradeMarket.ts`: from the League Year to the deadline GMs search for deals (buy at a need, sell veterans when rebuilding, move camp depth), at rates from the real counts by stretch of the year (`calibration/frontoffice.json`) scaled by trade appetite; deal sizes mostly small (real: about 5% of player deals include a 1st); person-run teams get offers (`league.tradeOffers`, a `trade-offer` decision) instead. Unhappy players (12b) are shopped through the same market (`shopPlayer`). Screens: the Trade page shows the other GM's answer and counter, and an offers inbox with a switch to answer a team's offers yourself (`controller: "human"`); the team page's Front office tab (`front-office/views.ts`). `exploits.test.ts` is the anti-exploit suite. Saves are format 17 (old saves get generated GMs and owners).
- **Owners and Simulation Mode (Phase 13b).** `front-office/owners.ts`: owners move the carousel's head-coach firing odds (`ownerCoachTerm`: patience, ambition, a meddler's per-season impulse by hash) and judge their GMs on Black Monday (`gmFiringOdds`: results against `expectedWinShare`, playoff droughts, losing runs, cap hell over 15% dead money, the contract, a new GM's grace, the owner's patience and ambition; tuned to about 4.5 GM changes a year, `calibration/frontoffice.json` `executives`). `hireGm` picks from out-of-work GMs and generated newcomers by skill, reputation and fit with the owner; a new GM may replace a head coach he didn't hire. An in-season head-coach firing sometimes takes the GM too. `executivesSeasonEnd`: career lines, reputations, renewals, retirements. `league.executiveMoves` logs every move with its reason. Team needs skip players out four games or more, so contenders shop for replacements at the deadline. Persistence (Phase 13b balance work): a winning team's players test the market less (`testMarket.winning`), starting quarterbacks rarely do (`starterQbTest`, QB tags to rank 16), rebuilders keep money back and pay less for players 29+, contenders pay more for veterans. `balanceReport.ts` + `npm run sim -- --frontoffices N`: results and habits by GM type, and parity (win-share spread and carryover, playoff repeats, worst to playoffs, champions a decade, five-year playoff and four-year losing runs) against `calibration/frontoffice.json` `parity`. Screens: `/simulation` (sim N seasons a season at a time with a stop button, power rankings from point margin and record or, before games, the league office's read of each roster, champions with their GMs, dynasties and droughts, every GM and his stance, front-office moves) and `/executive/:id` (`front-office/views.ts`). `npm run sim -- --carousel N` also counts GM changes. **History cards** (`lifecycle/archive.ts`): at each season's end, players retired or unsigned for `ARCHIVE.afterSeasons` (4) seasons leave `league.players` for `league.formerPlayers` (short cards: name, position, college, draft, first and last season, teams, seasons started, peak by the league office's read, career totals); draft history, the draft and career reports and the player page (`formerPlayerView`) read both. Names: `generate/names.ts` (337 first, 450 last); a retired player's name frees up after five seasons and `NamePicker` allows a repeat rather than loop forever. Saves are format 18.
- **GM Mode (Phase 14a, `sim-core/src/career/`).** `league.career` (null = Simulation Mode): the person's team, his executive (`person: true`, no AI knobs; owners skip him in reviews and retirement until 14b), delegation per area (`DELEGATION_AREAS`; `DEFAULT_DELEGATION` keeps the big calls, staff the upkeep) and a decision log. `startCareer` (`start.ts`) moves the AI GM aside, sets `controller: "human"` and "Viewing as" to his team, and returns the owner meeting. Every AI routine that acts for a team asks `staffDecides(league, teamId, area)` first (`delegation.ts`): re-signing, free agency and offer sheets, extensions, trades (market, draft-day trade-ups), disputes, coaching firings and hires, cutdown, practice squads, waivers, elevations. Cap compliance and roster limits always run (the safety net). Decisions for him go to `pendingDecisions` with a deadline (`inbox.ts` `ask`, once per subject); triggers in `staff.ts` (re-sign window: the offseason step splits in two, so the League Year waits a step; your pick on the clock: the draft step stops there; cutdown; extensions for starters in their last year, due at the trade deadline), disputes in `people/disputes.ts`, coaching vacancies in `coaches/carousel.ts`, trade offers in `tradeMarket.ts`. `advance()` closes what he settled on the screens (`tidyInbox`), hands anything due to his staff (`staffAtDeadlines`, the AI's own logic, a log line each), and gives decisions a step opened and passed a deadline until the next step (`giveTimeToNew`). Answers: `answers.ts` (tag, tender, let go, wait, done; others point to the negotiation, draft room or coaching screens). `delegate()` hands an area to the staff and settles its open items. The sim button "Sim to next decision" (`next-decision`) steps until something new or due needs him. In GM Mode the worker refuses moves for other teams (`assertYourTeam`) and the draft room's sims stop at his picks. Screens: `/career/start` (team list with stance, owner, cap room; owner meeting) and `/inbox` (decisions by kind with deadlines, the owner, delegation switches, the log); the header shows an inbox count. `career/career.test.ts` plays three seasons as one team through the screens' functions with the legality audit on, and a fully delegated team for two. Saves are format 19 (older saves open in Simulation Mode).
- **The job (Phase 14b, `career/job.ts`).** The person is judged by the AI GMs' own `gmFiringOdds` (same draw label), plus `career.standing`: the owner's reactions to his moves (`ownerWatch`, after every step and save: trading a star, a big free-agent deal by the owner's budget trait, cap hell, paying out past his budget), sizes in `JOB` (judgment), fading by half each season. Job security on screen = 100 x (1 - the odds if the season ended today). The owner's cash budget is the league's median payout times his budget trait; a meddler vetoes a deal far past it (`ownerVeto` in `makeOffer`). Fired on Black Monday (`reviewPerson` in `ownerReviews`) or, rarely, in season (`inSeasonReview`): his team goes back to an AI GM, his inbox closes, and owners make offers (`jobOffers`: teams that changed GMs this year and GMs on the hottest seats, by his reputation and each owner's taste; never the team that fired him). He takes one (`takeJob`), waits (new offers next Black Monday) or retires (`retireCareer`; Simulation Mode). Tips (`tips.ts`, `career.tipsSeen`) and the glossary (`glossary.ts`, numbers from the rules file). Screens: `/career` (security meter, the owner's words, record by season, drafts with grades, trades, offers), `/glossary`, tips on the inbox. Saves: "Save a copy" on the league list, and a backup the first time each season is saved (Dexie `backups` table, last 3 per league; restore makes a new league).
- **League history (Phase 15, `sim-core/src/history/`).** The league keeps its story in `league.annals` (real seasons from before it began, compact), `awards`, `records`, `hallOfFame`, `retiredNumbers`, `news` and `formerPlayers` with `legend: true` cards for imported real retirees. `awards.ts`: after the championship, MVP, OPOY, DPOY, rookies, Comeback, Coach of the Year (votes: production z-score at the player's position, the team's record, and the voters' habits by position in `AWARDS.positionBonus`, fitted to the real winners' mix in `calibration/awards.json`; shares come from the score gaps, no draws), plus All-Pro first and second teams and the Pro Bowl by production and the league's read; Pro Bowls set the fifth-year option's top tiers (`fifthYearOptionSalary`, CBA Art. 7). `records.ts`: league (top ten) and franchise (top three) game, season and career lists, checked after each game and week; a record that changes hands keeps the old holder and makes news (league records always; franchise season and career records once old; a new book's first marks aren't news). `hallOfFame.ts`: five seasons after a player last played, 13 player finalists plus a coach and a general manager, 80% approval, 3-7 a class (`rules.hallOfFame`, from the Hall's own pages); approval is a logistic of the career case (All-Pros, Pro Bowls, MVPs, titles, records held, peak, years as a starter) with a first-ballot hurdle and a bonus for each year waited; inductees' teams retire numbers some of the time (`RETIRING`), and `assignJerseys` never hands them out again. Imported legends aren't on the ballot. `storylines.ts` and `news.ts`: the newsfeed (trades, big signings, coaching and front-office changes from the logs, and weekly streaks, MVP race, hot seats, starters lost for the year); `news.ts` keeps two seasons. `past.ts`: owners and the carousel read the league's own seasons plus the last ten real ones (`recentSeasons`), so deep history never counts. Screens (`views.ts`): `/history` (almanac: seasons, franchises, dynasties, droughts, Hall of Fame), `/season/:year`, `/records/:team?`, `/news`, the team page's History tab, the coach page's drawn tree (`coachTreeView`), honors on player pages (`honors.ts`). **The real past** (`npm run pipeline -- history`, `pipeline/src/history/`): fetches archived reference pages (award winners since 1966, every AP All-Pro team, the Hall of Fame, league and franchise leader lists, the last three Pro Bowls) politely into `pipeline/private/history/pages/` and, with a public game-by-game scores file in `private/history/raw/`, builds the annals (1966-2024), legends, awards, Hall, retired numbers and record books (`build.ts`, `annals.ts`, `records.ts`, `retired.ts`), renamed through the same Renamer as the players (a legend's name is a hash of his site id; all real names in the data are blocked from the fictional pool); `league` hands them to `assembleRealLeague` (`history/real.ts`). Franchise moves and renames follow the league's convention (a club that moved is one franchise; the league's 1996 expansion team is its own); the real clubs' names live only in the private `pipeline/private/history/team-names.json`. `calibration/awards.json` (derived counts only) holds the real winners' position mix, All-Pro and Pro Bowl slots and Hall class sizes. `npm run sim -- --history N` compares awards by position, Hall classes (and whether the best careers get in) and how often records fall with the real shapes. Saves are format 20.
- **Day One (Phase 16).** The real league file stays a snapshot of the first day of 2026; each new game from it plays out the 2025-26 offseason itself. The file keeps the real 2025 games in `league.priorSeason` (null in generated leagues and old saves; `startRealLeague` clears it). `coaches/startCarousel.ts` `runStartingCarousel` lends the league the 2025 season (season, date, games, calendar), runs Black Monday, the hiring rounds, `offseasonStaffing` and `executivesSeasonEnd` on the new game's own seed, and gives everything back, so each save has its own head-coach and GM changes (about 9 head coaches and 6 general managers per start; the real figures are 7.2 and 4.5 a year, so a start is a little busier than a typical year; recorded honestly in the devlog). The real 2026 schedule (nflverse, `pipeline/src/league/schedule.ts`) replaces the generated one (`applyRealSchedule`: 272 games, week, opponent, home side) and 2027 picks traded before Feb 9, 2026 (nfldata trades) move owners (`applyPickTrades`). `pipeline/src/league/dayOne.ts` `validateDayOne` writes the Day One report (`pipeline/private/out/day-one.json` and a section of `report.md`): per team, roster size, cap space against the published figure, 2026 and 2027 picks, contracts into 2026 against the real contracts file (only deals signed before the league year; the file is newer), the real schedule and the head coach, plus league-wide legality. 25 of 32 pass outright and 7 miss only on cap space for a known reason (the cap page was archived on another day). Screen: `/start` "Where things stand" (`sim-core/src/dayOne.ts` `dayOneView`: champion, top of the draft, cap room, biggest players whose deals ran out, the carousel's changes); a real league opens there. `docs/rebuild-guide.md` explains how to rebuild for a 2027 start. Saves are format 21.
